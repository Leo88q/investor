# Games Watchtower × Ecosystem Share

Инвесторский лендинг Leo Games Studio с дашбордом состояния экосистемы. React 19 + Vite, статическая сборка, read-only. Рабочая ветка: `arena/01a0cf4e-investor`.

Главный принцип: **на странице нет ни одного числа без источника**. Каждая цифра либо приходит из hub API с `source` + `dataQuality` + `asOf`, либо объявлена в `src/numbers.js` / `src/config.js` с указанием происхождения. Значения из `mock`-режима хаба показываются только с бейджем **DEMO DATA**. Отсутствующее значение печатается как «—», а не как `0` и не как вчерашнее число.

## Запуск

Node.js **22.12+**.

```bash
npm ci
npm run dev            # лендинг на 0.0.0.0:5173, /api проксируется на хаб
npm run dev:hub        # второй терминал: dev-фикстура хаба (mock) на 127.0.0.1:5174
npm test               # unit + рендер + клиент + линтер чисел + скан секретов
npm run build          # dist/index.html + dist/en.html
npm run preview        # production-сборка
```

Без `npm run dev:hub` запросы к `/api` завершаются ошибкой — и это правильное состояние: страница обязана показать «данные недоступны» с причиной, а не выдумать цифры. Смотрите `#status`, `#snapshots`, `#compliance` и баннер под шапкой.

### Переменные окружения

Скопируйте `.env.example` в `.env.local` (не коммитить). Все `VITE_*` видны в браузере: **никаких секретных ключей, токенов и приватных ключей mint**.

| Переменная             | По умолчанию | Назначение                                                                        |
| ---------------------- | ------------ | --------------------------------------------------------------------------------- |
| `VITE_SALE_OPEN`       | `false`      | Флаг подтверждённого запуска продажи                                              |
| `VITE_MARKETPLACE_URL` | пусто        | HTTPS-ссылка на marketplace                                                       |
| `VITE_FORM_ENDPOINT`   | пусто        | Внешний HTTPS endpoint или относительный путь формы                               |
| `VITE_CONTACT_URL`     | пусто        | `mailto:` либо HTTPS Telegram/email контакт                                       |
| `VITE_TERMS_URL`       | пусто        | HTTPS-ссылка на утверждённый полный документ прав                                 |
| `VITE_SITE_URL`        | пусто        | Канонический адрес, например `https://example.com/`                               |
| `VITE_API_BASE`        | `/api`       | База hub API; по умолчанию same-origin, чтобы браузер не ходил в localhost        |
| `VITE_API_TIMEOUT_MS`  | `8000`       | Таймаут запроса к хабу                                                            |
| `VITE_CONSENT_ENDPOINT`| пусто        | Endpoint журнала согласий студии (interlock i-02)                                 |
| `DEV_HUB_URL`          | `http://127.0.0.1:5174` | Куда dev-сервер проксирует `/api` (только dev)                        |

## Структура

- `src/content.js` — **единый объект RU/EN** со всей копией страницы, якорем данных, статусом экосистемы, снапшотами и юридическим блоком.
- `src/config.js` — единственный источник параметров сделки (цена, тираж, 25%, лимит 10/кошелёк, target), календаря снапшотов, гейта продажи, статуса mint и правовых полей.
- `src/numbers.js` — реестр чисел: значение, источник, `dataQuality`, `asOf`, флаг `demo`, происхождение (`config` / `brief` / `api`).
- `src/api.js` — read-only клиент хаба: никогда не бросает исключение, возвращает `{status, reason}`, нормализует payload'ы и отделяет `source: "mock"` от live.
- `src/math.js` — формула дивиденда, округление вниз до цента, клампы, календарь первого рабочего дня, форматтеры (`moneyOrDash`, `stampUtc`).
- `src/main.jsx` — страница и компоненты честных данных: `Metric`, `QualityBadge`, `DemoChip`, `MetricTrace`, `DataStateBar`, экраны `EcosystemStatus`, `Snapshots`, `Compliance`.
- `src/styles.css` — токены Watchtower, desktop/mobile, reduced-motion; шрифты объявлены через `local()` без блокирующих запросов.
- `scripts/` — `check-numbers.mjs` (линтер «нет чисел без источника»), `check-secrets.mjs`, `check-bundle.mjs`, `seo.mjs`, `dev-hub.mjs` (dev-фикстура).
- `tests/` — `math.test.js`, `numbers.test.js`, `render.test.js` (SSR-рендер с фикстурами), `client.test.js` (jsdom, реальный путь данных), `browser/*.spec.js` (Playwright).
- `docs/` — контракт `ecosystem/status`, interlocks, эксплуатация (SLO/DR/форензика), ответ по разделам A–F.

## Как устроена честность данных

1. **Один вход для цифр.** Любое число рендерится через компонент `Metric`. Он печатает значение, бейдж `complete | partial | unavailable`, чип `DEMO DATA` (если источник — mock) и раскрываемый след: источник, `asOf` в UTC, формулу, примечание. Забыть бейдж технически невозможно: он внутри компонента.
2. **Реестр.** `src/numbers.js` перечисляет каждое отображаемое число со ссылкой на источник и датой сверки. `src/config.js` остаётся единственным источником параметров сделки; раcхождение ловится тестом.
3. **Линтер.** `npm run test:numbers` парсит `content.js`, `main.jsx` и `index.html` (JSX-текст, строковые литералы, HTML-текст) и падает, если встречает число, которого нет в реестре или в списке обоснованных исключений. Геометрия, классы, hex-цвета и выражения не считаются утверждениями.
4. **API никогда не врёт молча.** `src/api.js` различает `endpoint_not_deployed`, `timeout`, `network_error`, `http_error`, `not_json`, `unknown_endpoint`. Любая ошибка → явный статус с причиной и кнопкой повтора. Старые значения не подставляются.
5. **Состояние экосистемы — только из хаба.** Уровни L0–L4, подключения и причины приходят из `GET /api/ecosystem/status`. Пока эндпоинт не реализован, экран говорит об этом прямо и показывает словарь уровней как документацию, а не как присвоенные уровни. Контракт: `docs/ECOSYSTEM_STATUS_API.md`.
6. **Нулевой квартал не прячется.** Прибыли нет → `$0` и объяснение «квартал без прибыли — выплата $0». Отсутствие данных и ноль выглядят по-разному.

## Выплаты

Формула из брифа: `дивиденд на NFT за квартал = (чистая прибыль студии за квартал × 25%) / 100`. В коде — `calculateShare`, округление всегда **вниз** до цента, чтобы выплата не превысила пул. Снапшот — первый рабочий день января, апреля, июля, октября (UTC); права переходят покупателю со следующего снапшота. Би exchange-праздники **не** смоделированы: правило сдвига даты должен утвердить оператор — выдуманная дата была бы выдуманным числом.

Таблица снапшотов берёт строки из `GET /api/investors/snapshots` и ссылается на источник по каждому кварталу. Прибыль за квартал хаб пока не публикует: колонки пула и выплаты показывают «—», а не расчёт «по похожим данным». Как только хаб добавит `netProfit` в отчёт снапшота, таблица включится без изменений на лендинге.

```bash
npm run test:numbers   # «нет чисел без источника»
npm run test:secrets   # нет ключей, токенов, seed-фраз, .env
npm run build && npm run test:bundle   # JS < 200 kB gzip, CSS < 40 kB gzip
```

Браузерные тесты (Playwright, нужны бинарники):

```bash
npx playwright install --with-deps chromium   # или готовый Chromium: CHROMIUM_PATH=/path/to/chromium
npm run dev:hub & npm run dev &
npm run test:e2e                              # 25 прогонов: landing + honest-data
```

Спеки проверяют оба языка, клавиатуру, focus trap, калькулятор, недоступность формы, отсутствие переполнения на 360/390/768/1024/1440 px, а `tests/browser/honest-data.spec.js` — бейджи качества, DEMO DATA на mock-ответе, след источника у каждой цифры, нулевой квартал, поведение при мёртвом хабе, журнал согласий и axe (WСAG 2 A/AA).

Форма проверяется отдельным сервером: `VITE_FORM_ENDPOINT=/api/waitlist npm run dev -- --port 5173`, затем `TEST_FORM=1 npx playwright test tests/browser/form.spec.js` (4 прогона: успех, 500, HTML-ответ, `{"ok":false}`). Запрос перехватывается локально, реальные email не отправляются.

## Лид и согласия (i-02)

Без endpoint поле и кнопка отключены, email не сохраняется. Настроенный endpoint получает контракт:

```http
POST <VITE_FORM_ENDPOINT>
Content-Type: application/json

{ "email": "...", "language": "ru", "source": "watchtower-investor",
  "consents": { "email": true, "analytics": false, "version": "2026-09-23",
                "termsVersion": "investor-lead-v1" } }
```

Четыре исходных ключа сохранены без изменений — это зафиксировано тестом. Журнал согласий пишется в `localStorage` **до** отправки (ключ `watchtower.investor.consents.v1`), кнопка «Отозвать согласие» обновляет запись (`email: false`), а при заданном `VITE_CONSENT_ENDPOINT` запись уходит в сервис согласий студии. Антиспам: honeypot-поле, минимальное время заполнения и cooldown из `src/config.js`.

## Деплой

- **Vercel:** framework Vite, build `npm run build`, output `dist`, заполнить env, rebuild.
- **GitHub Pages:** опубликовать содержимое `dist`; `base: './'` работает под `/investor/`, `VITE_SITE_URL` должен включать путь.
- `/api` в продакшене проксируется на хаб на уровне CDN/реверс-прокси. Лендинг не хранит секретов и не пишет в блокчейн.

`scripts/seo.mjs` создаёт `en.html`, canonical/hreflang, абсолютные `og:image` и `twitter:image`, `robots.txt`, `sitemap.xml` и JSON-LD (`Organization` + `Product`/`Offer`). В разметке нет выручки, игроков и доходности — только подтверждённые параметры предложения; доступность (`PreOrder`) берётся из того же гейта `saleReady`, что и кнопка покупки.

## Границы и оговорки

- Интерфейсы Watchtower на странице — интерактивные макеты. Подписи `DEMO DATA` сохраняются до появления оригинальных скриншотов и live-данных.
- Дивидендный контракт, аудит, доступ холдеров и выплаты — **planned**. Схема 50/30/20 — предложение до подтверждения.
- Годовые сценарии — **не прогноз**. Квартальный эквивалент иллюстрации предполагает равномерную прибыль; фактические выплаты зависят от результата квартала.
- Юридический текст — черновик; квалификация NFT зависит от юрисдикции и должна быть подтверждена юристом. KYC/AML, налоги и ограниченные юрисдикции публикуются до открытия продажи.
- Блок команды отсутствует до получения био основателя.
