# Games Watchtower × Ecosystem Share

Двуязычный инвесторский лендинг Leo Games Studio. React 19 + Vite, статическая сборка, без кошелька, mint-логики и серверной базы. Рабочая ветка: `arena/01a0c49b-investor`.

## Запуск

Node.js **22.12+**.

```bash
npm ci
npm run dev           # 0.0.0.0:5173
npm test              # расчёты, язык, симметрия переводов, стадии
npm run build         # dist/index.html + dist/en.html
npm run preview       # production-сборка
```

### Браузерные тесты

Запустите dev-сервер в отдельном терминале, затем:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

`TEST_URL` меняет адрес проверяемого сайта. `CHROMIUM_PATH` позволяет использовать установленный Chromium. Тесты проверяют оба языка, URL/back, 4 вкладки demo (включая клавиатуру), сценарии калькулятора, focus trap в Terms, FAQ, неактивную форму, картинки, якоря и отсутствие горизонтального скролла на 360/390/768/1024/1440 px.

Для проверки **настроенной** формы запустите отдельный dev-сервер с `VITE_FORM_ENDPOINT=/api/waitlist npm run dev -- --port 5174`, затем:

```bash
TEST_URL=http://127.0.0.1:5174 TEST_FORM=1 npx playwright test tests/browser/form.spec.js
```

Эти тесты перехватывают запрос локально: реальные email не отправляются. Проверяются подтверждённый успех, HTTP-ошибка, HTML вместо ответа формы и отказ в JSON.

## Структура

- `src/content.js` — **единый объект RU/EN** с копией страницы, FAQ, черновиком Terms и юридическим текстом.
- `src/config.js` — параметры сделки и переменные интеграций.
- `src/math.js` — проверяемые расчёты (убыток/ноль → нулевая выплата), USD-формат, выбор языка.
- `src/main.jsx` — страница, интерактивный макет Watchtower, калькулятор, форма и доступный модальный Terms.
- `src/styles.css` — токены Watchtower, desktop/mobile, reduced-motion.
- `public/images/*.webp` — **AI-generated concept art**, не скриншоты игр.
- `public/og.svg`, `public/og.png` — scaffold Open Graph 1200×630.
- `scripts/seo.mjs` — статические RU/EN metadata, canonical, hreflang и sitemap после Vite build.

## Что намеренно НЕ выдаётся за готовую функциональность

- В репозитории не было Watchtower или его скриншотов. Все показанные интерфейсы — **специально созданные интерактивные макеты**, а не «реальный интерфейс». У них постоянные `DEMO DATA` и подпись. График схематический, без DAU/выручки и без числовой оси.
- Цифры 4/6/1/100, 5/8/6/$0 взяты из брифа. Шесть органических каналов трактуются как SEO, GEO, X, видео, радар, TipLink. Это не посещаемость. Фактические стадии продуктов и live-статус TalkChart приведены **со слов студии**, без независимой проверки.
- Нет счётчика «продано», фиктивной срочности, транзакций, обещания доходности, выдуманных биографий и слотов несуществующей команды.
- Дивидендный контракт, аудит, доступ холдеров и выплаты — **planned**. Схема 50/30/20 — предложение до подтверждения. Публичные ссылки на код и аудит не выдумываются.
- Снапшот — первый **рабочий** день января/апреля/июля/октября, не гарантированно первое число. Юрисдикция, рабочий календарь и срок выплаты должны быть определены в Terms.
- Юридический текст — черновик. Убрано безусловное утверждение, что NFT «не является ценной бумагой»: классификация зависит от юрисдикции и должна быть подтверждена юристом.
- Годовые сценарии — **не прогноз**. Квартальный эквивалент иллюстрации предполагает равномерную годовую прибыль. Реальные выплаты зависят от фактического результата квартала.

## Параметры интеграций

Скопируйте `.env.example` в `.env.local` (не коммитить). Все `VITE_*` доступны браузеру: **никаких секретных ключей**.

| Переменная             | Значение по умолчанию | Назначение                                                                                         |
| ---------------------- | --------------------- | -------------------------------------------------------------------------------------------------- |
| `VITE_SALE_OPEN`       | `false`               | Флаг подтверждённого запуска продажи                                                               |
| `VITE_MARKETPLACE_URL` | пусто                 | HTTPS-ссылка на реальный marketplace                                                               |
| `VITE_FORM_ENDPOINT`   | пусто                 | Внешний HTTPS endpoint или относительный путь формы                                                |
| `VITE_CONTACT_URL`     | пусто                 | `mailto:` либо HTTPS Telegram/email contact URL                                                    |
| `VITE_TERMS_URL`       | пусто                 | HTTPS-ссылка на утверждённый полный документ прав                                                  |
| `VITE_SITE_URL`        | пусто                 | Канонический адрес с путём, например `https://example.com/` или `https://user.github.io/investor/` |

### Продажа

Покупка включается **только** при `VITE_SALE_OPEN=true` и заполненных HTTPS `MARKETPLACE_URL` + `TERMS_URL`. До этого CTA ведёт к листу ожидания. На странице нет mint-контракта и прямого взаимодействия с кошельком. Ограничение 10 NFT/кошелёк и отключение mint должны реализовываться в marketplace/контракте — лендинг не обеспечивает их сам.

Числовые рабочие параметры находятся в `src/config.js`: $1,000, 100 NFT, 25%, 10/кошелёк, $100,000. Если меняете условия сделки, одновременно обновите утверждённую копию в `content.js`, изображение OG, бюджет и иллюстрации: текст брифа намеренно не переписывается автоматически. `npm test` фиксирует исходную математику, поэтому при смене модели пересмотрите тесты. Тиры не реализованы, используется единственный класс.

### Лист ожидания

Без endpoint **поле и кнопка отключены**, email не сохраняется ни в localStorage, ни в базе. Сообщение объясняет, что подписка скоро откроется.

Настроенный endpoint получает:

```http
POST <VITE_FORM_ENDPOINT>
Content-Type: application/json
Accept: application/json

{"email":"investor@example.com","language":"ru","source":"watchtower-investor"}
```

Успех: HTTP 2xx и JSON `{"ok":true}` или `{"success":true}`. HTML от static fallback, `ok:false`, ошибочный JSON и не-2xx не считаются успехом. Таймаут 15 секунд; при ошибке email остаётся для повторной отправки. Backend/форм-сервис должен обеспечить CORS для публичного origin, серверную валидацию, антиспам/rate limiting, хранение, удаление данных и требуемые privacy/consent документы. Подключайте только утверждённый сервис; сама страница не притворяется сервером рассылки.

## Языки и SEO

- RU по умолчанию; `?lang=en` / `?lang=ru` сохраняются при переходах по якорям.
- Переключение без перезагрузки, Back/Forward поддерживаются; обновляются `<html lang>`, title, description и OG locale.
- Сборка дополнительно создаёт `en.html` с английскими metadata для социальных роботов, не исполняющих JS. Для публичного EN preview делитесь `/en.html`, для пользовательской навигации — `?lang=en`.
- При заданном `VITE_SITE_URL` создаются абсолютный OG URL, canonical/hreflang, `robots.txt` и `sitemap.xml`. Без него универсального production URL не выдумываем.
- Manrope / DM Mono загружаются с Google Fonts с `display=swap`, предусмотрены fallback-шрифты. При необходимости автономного/CSP-строгого деплоя сохраните лицензированные WOFF2 локально.

## Деплой

### Vercel

Импортировать репозиторий → framework **Vite** → build `npm run build` → output `dist`. Заполнить env, затем rebuild. Backend не нужен. Не включайте продажи до прохождения чек-листа.

### GitHub Pages

Собрать `npm ci && npm run build`, опубликовать **содержимое `dist`** через Pages artifact/action. `base: './'`, локальные картинки и favicon работают под `/investor/`. `VITE_SITE_URL` должен включать путь репозитория. Не требуется SPA-rewrite для якорей и query-параметров; `en.html` — реальный файл.
