# Эксплуатация, устойчивость, форензика и комплаенс

Документ отвечает на горячие риски W4. Каждый пункт либо реализован и проверяется, либо помечен как **не реализовано** — потому что выдуманное «соответствие» хуже его отсутствия.

## o-02 — SLO и публичная отчётность

| Показатель                  | Цель                        | Статус                                                                 |
| --------------------------- | --------------------------- | ---------------------------------------------------------------------- |
| Доступность лендинга        | ≥ 99.9% в месяц             | Цель опубликована на странице. Публичных отчётов о доступности пока нет. |
| p95 ответа публичного API   | ≤ 300 мс                    | Цель опубликована. Замеры делает хаб; лендинг их не измеряет и не публикует. |
| Свежесть данных в интерфейсе| штамп `asOf` в UTC          | Реализовано: баннер под шапкой, `DataStateBar`, след у каждой метрики.   |
| Деградация при сбое хаба    | явный статус с причиной     | Реализовано и покрыто тестами (`reason`: `timeout`, `network_error`, `http_error`, `not_json`, `endpoint_not_deployed`). |

Что нужно от оператора: страница статуса (внешний URL) и процедура публикации инцидентов. Пока их нет, `config.ops.slo.statusPageUrl` пуст, и лендинг показывает только цели, а не факты.

## o-05 / o-06 — DR, SBOM, релиз и откат

**Реализовано в этом репозитории**

- Контент и параметры сделки — это код: `src/content.js`, `src/config.js`, `src/numbers.js` версионируются вместе со страницей. Резервная копия контента и конфигурации = git-история плюс артефакт сборки в CI (`dist`, 7 дней).
- Откат = переустановка предыдущего артефакта: сборка детерминирована (`npm ci` + `npm run build`), версия фиксируется по коммиту.
- SBOM: `npm ci` + `package-lock.json` дают полный список зависимостей; CI запускает тесты и сборку на чистом клоне, что ловит несоответствие lock-файла.
- Секреты: `scripts/check-secrets.mjs` сканирует рабочее дерево, CI дополнительно сканирует **историю** git на ключевой материал. Приватные ключи mint в репозиторий не попадают ни в каком виде.

**Требуется от оператора**

- [ ] Хостинг с версионированием артефактов и мгновенным откатом (Vercel/Pages deployment rollback).
- [ ] Публикация SBOM как артефакта релиза (CycloneDX/SPDX).
- [ ] Runbook: кто и как откатывает страницу, кто отключает продажу (`VITE_SALE_OPEN=false` + rebuild), кому сообщается.

## o-07 — форензика и аудит публикаций

| Артефакт                          | Где                 | Что фиксирует                                                    |
| --------------------------------- | ------------------- | ---------------------------------------------------------------- |
| Журнал согласий                   | браузер посетителя  | `watchtower.investor.consents.v1`: согласие, отзыв, время, язык   |
| Синхронизация согласий            | `VITE_CONSENT_ENDPOINT` | `sendBeacon` в сервис согласий студии (когда задан)           |
| Кто и когда опубликовал числа     | git + реестр        | Каждое число имеет `source` и `asOf`; линтер не даёт добавить число без записи в реестре |
| Публикация снапшота               | правило            | Снапшот появляется в таблице только если он есть в ответе хаба. Публикация выполняется **после подтверждения оператором** и фиксации отчёта (`immutable: true`); лендинг ничего не публикует сам |
| Провенанс каждого показателя      | интерфейс          | След у метрики: источник, `asOf` UTC, формула, примечание         |

Ограничение, которое нужно знать: журнал согласий в браузере — это клиентская запись, а не серверный аудит. Полноценный форензик-журнал требует серверного приёма (endpoint формы/согласий) с неизменяемым storage — это задача оператора.

## Комплаенс: что публикуется до продажи

Реализовано как интерфейс (`#compliance`), но каждая строка ниже закрывается только оператором:

| Пункт                            | Состояние сейчас                              |
| -------------------------------- | --------------------------------------------- |
| Disclaimer (NFT ≠ доля в капитале, риск потери, USDC on-chain) | Опубликован как черновик |
| KYC / AML                        | Провайдер не выбран, статус «ожидает решения оператора» |
| Ограниченные юрисдикции          | Не опубликован: юрлицо и регистрация не определены |
| Налоговая логика выплат          | Не подтверждена; студия не даёт налоговых консультаций |
| Адрес программы mint + мультиподпись | Не публикуется до подтверждения; выдуманный адрес не появится — это проверяется тестом |
| Аудит контракта                  | Не проведён |
| Terms of the Share               | Черновик; продажа закрыта до утверждения |

Юридическая проверка перед публичным mint — **решение оператора**, а не автоматический шаг пайплайна. Гейт продажи технически жёсткий: `saleReady = VITE_SALE_OPEN && https MARKETPLACE_URL && https TERMS_URL`. Отсутствие любого из трёх оставляет CTA на лист ожидания, а JSON-LD на `PreOrder`.

## Что публикует сам лендинг

- Числа — только из хаба или из реестра, всегда с бейджем качества и `asOf`.
- Цели SLO — как цели, с явной пометкой, что публичных отчётов пока нет.
- Юридический текст — с пометкой «черновик» и перечнем незакрытых пунктов.
- Ничего о доходности: исторические значения и иллюстрации формулы подписаны «не обещание».
